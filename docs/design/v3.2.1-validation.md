# v3.2.1 首轮插件化实现与验证

> 历史开发记录。v3.2.2 已整理为正式版本，当前行为与验证见 [正式验收](v3.2.2-validation.md) 和 [图文使用说明](../versions/v3.2.md)。

本轮已按确认的架构迁移三个功能。代码位于 `dev/v3`，未发布 GitHub，也未冻结对外 SDK。本文是实现记录，不是插件开发手册。

## 已实现

- `electron/plugins/registry.mjs` 注册音乐、系统通知、Codex 三个内置 Provider。
- `electron/plugins/host.mjs` 统一启停、取消、状态校验、命令路由、提醒、已读和失败处理。
- `electron/plugins/capabilities.mjs` 与 `windows-adapter.mjs` 按订阅共用 Windows 桥接与 Codex 只读服务；禁用一个不会误停其他功能。
- `src/plugins/types.ts` 是前端共用契约，`renderer.ts` 按组件渲染页面。菜单与管理器不再枚举三个功能 ID。
- 插件管理器显示版本、状态、开关、重启、权限、自己的设置与兼容说明。功能页和插件页共用一个启用状态。
- 保留悬停、固定、滚动吸附、每页来源标题、面板缩放、通知已读撤点与空态入口。
- 开关、全局偏好、尺寸和屏蔽来源迁移到第二版设置文件；旧文件备份为 `feature-settings.json.v1.bak`。已读标识迁移到独立记录，不保存正文。
- 保留不认识的插件配置；不支持的应用或插件配置版本不会静默覆盖。

## 自动化验证

运行 `node --test scripts/test-plugins.mjs scripts/test-extensions.mjs scripts/test-startup.mjs scripts/test-character-parameters.mjs` 验证宿主、协议和核心功能回归。

运行 `pnpm build` 后，通过 `pnpm test:plugins:ui` 在独立配置与演示数据中检查真实 Electron 窗口。覆盖插件动态注册、悬停固定、连续滚动吸附、来源标题、命令 IPC、缩放保存、已读撤点、设置同步、重复打开以及退出后的鼠标捕获释放。

第四插件仅供测试，用来证明新增插件无需修改菜单、渲染器和管理器。正常运行仍只有三个内置插件。测试截图和结果位于 `.local/v321-smoke/`，不会使用真实聊天正文。

## 本机只读验证

本轮通过 `scripts/probe-plugins.mjs` 使用独立配置验证，未执行播放/暂停操作，也未打印聊天正文、歌曲名称、任务名称或凭据：

- 网易云：检测到 `cloudmusic.exe`，有封面，时长/进度保持未知。
- 系统通知：权限 Allowed，实际检测到 QQ 系统通知。
- 微信与企业微信：运行中但未检测到系统通道通知，继续明确提示暂不支持。
- Codex：两个页面正常，已读取到额度。
- 三项能力共用一个 Windows 桥接进程；本轮保留既有底层协议，未扩大 Codex 操作权限。

本机结果代表当前环境，不承诺其他客户端版本都兼容；QQ 五种媒体命令经受控接口与演示适配器验证，此轮现场正在运行的是网易云。

## 仍保留的边界

接口 v1 为内部验证接口，后续可调整。第三方插件安装、市场、不可信代码沙箱、自定义 HTML、独立存储能力和插件开发手册未在本轮交付。内置 Provider 是受信任代码，统一权限清单不能当成恶意第三方代码的安全隔离。

后续独立待办阶段已补充 ZIP 安装、受限沙盒与独立存储，详见 [待办 ZIP 插件验收](zip-plugin-todo-validation.md)。上文记录的是三项内置插件首轮验收边界。
