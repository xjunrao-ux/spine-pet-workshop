# Spine 桌宠工坊 v2.2.4 使用说明

v2.2 是独立于 v2.1 和后续 v3 的可换角色封装版。应用内置阿米娅作为示例，也可以从本机导入其他 Spine 3.8 模型和角色语音。导入过程不会上传网络。

## 一、启动与打开角色管理器

首次启动会同时打开桌宠和“Spine 桌宠工坊”管理窗口。以后可以通过以下任一方式重新打开：

1. 右键桌宠，选择“打开角色管理器…”；
2. 右键系统托盘中的桌宠图标，选择“打开角色管理器…”。

管理器包含“角色库”“导入角色”“素材与格式”三个页面。

## 二、准备 Spine 模型

本版渲染器是 **Spine Runtime 3.8**。一个可导入的模型文件夹至少需要：

```text
角色文件夹/
├─ character.skel       骨骼与动画；也支持 Spine 3.8 JSON
├─ character.atlas      图集描述
└─ character.png        一张或多张贴图，也支持 JPG/WebP
```

模型文件可以放在子目录中，程序会保留其相对路径。图集内引用的贴图名称和路径必须与实际文件一致。

### 明日方舟基建小人下载位置

- Ark-Models：<https://github.com/isHarryh/Ark-Models>
- 基建小人在仓库的 `models/` 目录；动态立绘在 `models_illust/`。
- 仓库根目录的 `models_data.json` 可用于查找角色 ID。
- 如果只需要一个角色，建议在 GitHub 中进入对应角色目录后按需下载，不必下载约 1 GB 的完整仓库。

Ark-Models 的说明指出，明日方舟模型需要 Spine Runtime 3.8，一套模型通常由 `.skel + .atlas + .png` 组成。本程序正是按这个格式导入。

## 三、准备语音

程序支持两种并列的导入方式：已经切好的单句音频，或 Ark-Voice 的角色长音频。v2.2.4 默认内置时间轴和简中台词表，普通使用只需选择角色长音频；新角色或新版本也可以在“更新或覆盖内置配置”中选择新的 JSON。

### 明日方舟语音下载位置

- Ark-Voice：<https://github.com/isHarryh/Ark-Voice>
- `voice/`：日语；`voice_cn/`：普通话；`voice_en/`：英语；`voice_kr/`：韩语。
- 时间轴数据来源：Ark-Voice 仓库的 `voice_data.json`，已内置离线副本。
- 中文字幕来源：ArknightsGameData 简中 `charword_table.json`，已内置离线副本。

### 自动分句 + 日语语音 + 中文字幕

只需要 Ark-Voice `voice/` 目录中该角色的日语长音频。选择音频后，程序会从 `char_数字_代号.ogg` 文件名自动识别角色 ID；如果文件被改过名，可以手工填写，例如阿米娅是 `char_002_amiya`。

在“语音与字幕 → 方案 B”选择长音频，检查角色 ID，语种选择“日语 JP”。程序会使用内置时间点自动播放其中一条语音，并配对中文台词；不会在磁盘上生成大量切片。

长音频必须与所选角色及语种一致。例如选择 JP 时，应选择 `voice/` 下的日语音频，不能误选 `voice_cn/`。内置时间轴的上游数据版本为 2025-02-02；以后新增且未收录的角色可以展开高级选项，用新版 `voice_data.json` 和/或 `charword_table.json` 覆盖默认数据。

## 四、导入角色

1. 打开“导入角色”页面，填写角色名称。
2. 点击“选择模型文件夹”，选择同时包含骨骼、atlas 和贴图的目录。
3. 如果目录里有多套模型，选择正确的主骨骼文件和图集文件。
4. 可选填写动作映射。常见明日方舟基建动作是：
   - 待机：`Relax`
   - 行走：`Move`
   - 坐下：`Sit`
   - 躺下：`Sleep`
   - 点击：`Interact`
   - 特殊：`Special` / `SpecialIdle`
5. 语音可二选一：
   - 方案 A：点击“添加单句音频”，并为每条音频填写字幕；
   - 方案 B：只选择 Ark-Voice 角色长音频，程序用内置配置自动分句并匹配中文字幕。
6. 点击“导入并设为当前桌宠”。素材复制完成后，桌宠会自动重新载入。

动作映射可以留空，程序会按常见英文名称自动匹配。某个模型没有坐下或躺下动画时，对应菜单动作不会生效，但其他动作仍可使用。

## 五、角色库与数据位置

- “应用”：切换角色，桌宠会立即重新加载。
- “删除”：删除该角色以及程序复制的模型和语音；不会删除原始下载文件。
- 内置阿米娅不能删除，可随时切换回来。

Windows 默认角色库位置：

```text
%APPDATA%\spine-pet-workshop\characters\
```

每个角色包含 `character.json`、`model/` 和可选的 `voice/`。请不要在程序运行时手工改动这些文件。

## 六、兼容性排查

- 提示缺少骨骼：确认有 `.skel` 或 Spine JSON。
- 提示缺少图集/贴图：确认 `.atlas` 和 PNG/JPG/WebP 位于所选文件夹内。
- 模型加载失败：最常见原因是骨骼导出版本不是 Spine 3.8，或 atlas 引用的贴图名称不一致。
- v2.2.2 会自动解析 atlas 贴图页，并兼容 `#/?/%` 特殊字符；当 atlas 保留旧贴图名但同目录只有一张可匹配贴图时，也会自动修复映射。
- 模型不动：在动作映射中填写该模型真实的动画名称。
- 坐姿吸附不准：程序会依次查找 `F_Hip`、`Hip`、`Hips`、`Pelvis`、`Waist` 等骨盆骨骼；完全没有这类骨骼时才退回通用坐姿基准。
- 坐下悬浮：v2.2.2 已移除旧版额外 14% 抬升，骨盆支撑点会直接贴合窗口/任务栏上沿。
- 腿被任务栏遮住：默认“始终置顶”使用可覆盖任务栏的窗口层级。关闭始终置顶后，Windows 任务栏仍可能盖住模型。
- 自动分句失败：检查角色 ID、语种和长音频是否对应。若是 2025-02-02 之后新增的角色，可能尚未出现在内置时间轴中。
- 没有声音：确认语音开关已开启、音频可由 Chromium 播放，并重新检查导入文件。
- 语音边界异常：v2.2.4 移除了旧版 60ms 尾部宽限，并在下一句开始前约 12ms 精确停止，避免串入下一条。计时从实际播放后开始，缓冲或 seek 不会提前消耗句子时长。
- 播放被打断：除点击角色主动换句、关闭语音、切换角色或退出外，待机轮播和动作切换不会抢占当前语音。
- 坐姿略低：v2.2.4 在骨盆贴边基准上增加了 2% 窗口高度的轻微上移，不会恢复旧版过高的 14%。
