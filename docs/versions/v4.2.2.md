# v4.2.2 · 共同协议与通用本地服务能力

> 历史版本记录。当前正式版请阅读 [v5.1.2 使用说明](v5.1.2.md)。

本地开发版，尚未发布 GitHub Release。交付共同协议、通用宿主基础能力，以及独立桌宠 DSH 插件 1.0.0。已有 DSH 服务与桌宠插件完成模拟 Harness 的真实 HTTP/SSE 和 Electron 沙盒验证；连接用户真实 DSH 仍需手工授权。自动配对、反向待办工具、人设远程同步和自动记忆尚未交付。

- 定义 [pet-dsh/1](../DSH_BRIDGE_PROTOCOL.md)：会话、消息、事件、取消、审批、反向工具、人格与恢复语义，附 [JSON Schema](../schemas/dsh-bridge-v1.schema.json)。
- 新增通用 `net.local` / `context.localService`：用户授权的明确 loopback 根路径、加密连接令牌、异步 HTTP JSON 请求和 SSE 订阅。
- 使用宿主可信配置窗口登记地址和令牌；插件不能读取凭据或任意联网。连接直接访问数字 loopback，不使用环境代理、cookie 或重定向。
- 完成请求/事件预算、取消、超时、订阅释放与权限撤销；保持插件 API v1，原 DeepSeek、天气、Codex、待办等能力继续使用。
- 宿主不提供 context.dsh，不解析 DSH 消息，不扫描端口或读取 ~/.dsh。协议实现和界面业务留给插件。

开发者接口与示例见 [通用本地服务 API](../LOCAL_SERVICE_API.md)。使用该能力的 ZIP 需要升级宿主；用户在插件提供的连接设置按钮中授权服务地址和令牌。保存配置并不代表 DSH 已连接。

验证命令：`pnpm test:local-service`、`pnpm test:local-service:sandbox`、`pnpm test:deepseek`、`pnpm test:release`、`pnpm build`。验证结果以实际运行报告为准；不会宣称已经完成 DSH 双端业务验收。

## DSH 桌宠插件（2026-10-21）

使用 pnpm package:dsh-pet 生成 release/plugins/DSH-Pet-Plugin-v1.0.0.zip，在“扩展”导入。按 [安装指南](../../examples/dsh-pet-plugin/README.md) 保存 DSH 服务地址和连接令牌，再选择已有授权会话。

支持对话、任务摘要、停止确认、能力控制的追加指令、断线和回执恢复、本机资料与可选提醒。审批仍在 DSH 处理，本机资料不注入 DSH。[实现说明](../PET_DSH_PLUGIN_IMPLEMENTATION.md)与[测试报告](../DSH_PET_PLUGIN_TEST_REPORT.md)区分模拟 Harness、真实 Electron 与尚未执行的真实用户 DSH 验证。
